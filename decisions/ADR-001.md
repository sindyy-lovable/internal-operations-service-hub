# ADR-001: Maintain Request History

## Problem

The system needs to show the current state of a Service Request while also keeping important changes traceable.

If only the current status is stored, previous status changes, handling updates, and department transfers may be lost. This would make it difficult to understand how a request progressed from submission to completion.

## Options Considered

### Option 1 - Store Only the Current State

The system could store only the current status and current department of a request.

This would keep the model simple, but previous changes and transfers would not remain available.

### Option 2 - Store the Current State and Request History

The system could keep the current state on the Service Request and also record important status changes, handling updates, and department transfers in Request History.

This requires storing additional information, but it supports request tracking and traceability.

## Decision

The system will keep the current state on the Service Request and maintain a separate Request History for important changes.

Request History will record important status changes, handling updates, and department transfers. This allows the current request information to remain easy to access while previous important changes remain traceable.

## Consequences

This decision requires the system to store more information than keeping only the current state.

It also requires important changes to be recorded consistently in Request History.

In return, users can track request progress more clearly, and the system can preserve important information about how a request changed from submission to completion.
